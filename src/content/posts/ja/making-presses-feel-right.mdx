インターフェースは、ユーザーの声を聞いていると感じられるべきです。フォームを送信したら読み込み中の状態を、コピーしたら完了の状態を、できるだけ早く見せる必要があります。

いちばん簡単な方法は、ボタンを押したときに少しだけ縮めることです。`:active` の状態に `scale(0.97)` をひとつ加えるだけで十分です。

<Demo caption="ボタンを押してみてください。右側は押している間 0.97 倍に縮みます。">
  <Button press={false}>貼り付け</Button>
  <Button>貼り付け</Button>
</Demo>

## よく見るものほど、動かさない

一日に何十回も目にする要素は、動きを減らすか、なくします。このブログでは次のように決めました。

- リストのホバー背景は、トランジションなしですぐに変わります
- ホバーで変わるのはリンクの下線の色だけです
- キーボードで行った操作はアニメーションしません

```css
.row:hover {
  background: var(--color-bg-row-hover);
  /* トランジションなし:一日に何十回も見る要素 */
}

.button:active {
  transform: scale(0.97);
  transition: transform 160ms var(--ease-out);
}
```

動きを削ると、残るのは文字です。だからこのブログでは文字サイズをひとつだけ使い、*太さと色*だけで区別します。[^1]

<Quote author="Emil Kowalski" source="Building a Toast Component">
  ユーザーが気づくディテールは、少ないほどいい。
</Quote>

良いディテールは目立ちません。そのかわり、積み重なります。ひとつひとつは聞こえないほど小さくても、すべてが同じ音を奏でるとき、全体が違って感じられます。

[^1]: タイトルと h2 も本文と同じ 16px です。韓国語だけ 1px 大きくしています。
